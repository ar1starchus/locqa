О Grand Mobile
Grand Mobile - мобильная ролевая игра в открытом мире. Игрок создает персонажа,
устраивается на работу, вступает во фракцию или семью, покупает дом, машину и бизнес,
живет в городе вместе с тысячами других игроков на одном сервере. Можно быть таксистом,
полицейским, мэром или гангстером.
Игру делает студия из Казахстана, резидент Astana Hub. У игры более 55 млн установок и
более 500 тыс. игроков ежедневно. Серверы работают в СНГ, Казахстане, Узбекистане,
Европе и Латинской Америке. Клиент локализован на русский, казахский, узбекский,
английский, испанский и португальский.
Технически это собственный движок и клиент под Android и iOS, серверная игровая логика,
лаунчер и весь внутриигровой интерфейс на Flutter, бэкенд на Node.js с MariaDB и ClickHouse.
Каждое действие игрока с деньгами, каждая авторизация, каждое сообщение в чате и
каждое действие администратора пишутся в аналитические логи. На этих логах и построены
кейсы.

Контекст
Интерфейс игры локализован через стандартные ARB-файлы Flutter: около 5 500 строк на
каждый из 6 языков. Казахский для нас приоритет, потому что Казахстан - домашний рынок.
При этом в казахском файле более 200 строк дословно совпадают с русским оригиналом,
часть переводов выглядит машинной, одни и те же игровые термины переведены по-
разному в разных экранах, а длинные строки обрезаются в узких кнопках. Инструмента
проверки нет, носителей казахского в команде мало, проверка делается руками и редко.
Хакатон в Казахстане - лучшая возможность получить и инструмент, и качественный
перевод от носителей.
Задача
Сделать инструмент контроля качества локализации, который работает с любыми ARB-
файлами, и применить его к нашим файлам: найти проблемы, собрать глоссарий игровых
терминов, исправить казахский перевод с проверкой носителем.

Пункт про аффиксы важен: в казахском выбор окончания зависит от последнего звука слова, а имя

аффикса после плейсхолдера, либо помечать как требующие обработки в коде.

Критерии оценки
Детекция подложенных ошибок
Recall по 100 подложенным ошибкам с учетом типа. Precision по ручной проверке 100 случайных находок инструмента 35%
Качество исправлений
Слепая оценка носителями в жюри на 150 случайных измененных строк: исправленный вариант против исходного 35%
Универсальность инструмента
Работает на любом ARB без правок, документирован, покрыт тестами 15%
Объяснимость находок
У каждой находки понятные evidence и severity, мало шума в отчете 15%

Ограничения
LLM разрешены, в том числе внешние. Но «перевести все заново через LLM» не решение:
массовые непроверенные замены снижают оценку.
   Каждая измененная строка в intl_kk_fixed.arb помечена флагом проверки человеком.
Строки без проверки не идут в оценку качества.

Плейсхолдеры и ICU-синтаксис должны остаться валидными: файл обязан
   компилироваться стандартным flutter gen-l10n .
Бонус
Тот же анализ для узбекского.
Режим транслитерации казахского в латиницу по официальному алфавиту с проверкой
длины.
GitHub Action, который прогоняет проверку на каждый pull request с изменением ARB.
Автоматическое предложение переформулировки для строк с проблемой аффиксов.
Подводные камни
Часть совпадений с русским легитимна: названия брендов, ники, числа. Не считайте их
ошибками без разбора.
Игровой сленг устоялся у игроков: «варн», «мут», «фура», «ГК» вместо Grand Coins.
Глоссарий должен учитывать, как говорят игроки, а не только литературную норму.
Описания ключей есть не везде. Контекст иногда приходится восстанавливать по имени
ключа и соседним строкам.



# Qazaq Loc QA — данные кейса

Файлы локализации клиента Grand Mobile в формате ARB (Flutter).

| Файл | Что это |
|---|---|
| intl_ru.arb | Исходный язык. 5479 строковых ключей |
| intl_kk.arb | Казахский. В этот файл добавлено около 100 ошибок разных типов. Список у организаторов |
| intl_uz.arb | Узбекский, как есть |
| intl_en.arb | Английский, как есть |

## Особенности формата

- Плейсхолдеры записаны как `{name}`, `{count}`. ICU-плюралов в файлах нет.
- Метаданные `@key` есть только у нескольких ключей.
- Маркер `"@@comment"` повторяется много раз и делит файл на разделы. Строгий JSON-парсер оставит только последний; для анализа лучше читать файл построчно или через ARB-инструменты.
- Ключ `currencySymbol` содержит символ из private-use области шрифта игры. Это не ошибка.
- Файлы в UTF-8, Unix line endings.

## Что считать ошибкой

См. таксономию в описании кейса: untranslated, same_as_source, placeholder_mismatch, plural_mismatch, glossary_violation,
length_overflow (перевод заметно длиннее исходника для коротких элементов интерфейса), machine_translation_suspect, inconsistent_term, suffix_harmony, orthography. Дополнительно встречается wrong_language:
текст на другом языке в казахском файле. Совпадение с русским легитимно для брендов, имён и чисел.
